# 03. 진짜 서버에 올리기

**목표**: 인터넷에 24시간 켜진 컴퓨터를 한 대 빌리고, 도메인과 HTTPS를 붙이고, 손으로 첫 배포를 한다.

> 이 문서는 선생님이 한 번 준비하는 과정입니다. 수업에서는 완성된 서버에 SSH로 들어가 둘러보는 것만으로도 충분합니다.

## 무엇을 만드나

```
선생님 맥 ──ssh──▶  GCP 서버 (e2-micro, 미국 오리건, 무료)
                     ├─ Docker
                     ├─ /opt/wejump        (이 레포)
                     └─ deploy 사용자       (GitHub Actions가 접속할 계정)

DuckDNS:  wejump.duckdns.org  ──▶  서버 IP
```

**비용**: GCP 무료 티어(e2-micro 1대, 디스크 30GB, 외부 IP 포함)와 DuckDNS 모두 $0. 단 GCP 가입 때 카드 등록이 필요합니다.

## 0. 먼저: 이미지가 GitHub에 있어야 함

서버는 앱을 직접 빌드하지 않고, GitHub 창고(ghcr.io)에서 완성된 이미지를 받아 옵니다.

1. 레포를 GitHub에 올리면 Actions가 자동으로 이미지를 만듭니다. Actions 탭에서 `test`, `build`가 초록불인지 확인하세요. (`deploy`는 아직 설정이 없어서 건너뜀. 정상입니다.)
2. GitHub 프로필 → **Packages** → `wejump` 에서 이미지가 **Public**인지 확인합니다.
   서버가 로그인 없이 이미지를 받아 가려면 공개여야 합니다. 공개 레포에서 Actions로 올린 이미지는 보통 자동으로 공개가 됩니다. 만약 Private으로 되어 있으면 **Package settings** → 맨 아래 **Change visibility** → **Public**.
   이미지 안에 비밀이 없으므로 공개해도 안전합니다 ([02-도커](02-도커.md)의 `.dockerignore` 참고).

## 1. GCP 서버 만들기 (맥에서)

1. <https://console.cloud.google.com> 가입 → 결제 계정 연결 → 새 프로젝트 만들기. 프로젝트 ID를 적어 둡니다.
2. gcloud 설치와 로그인:
   ```bash
   brew install --cask google-cloud-sdk
   gcloud auth login
   ```
3. 서버 생성:
   ```bash
   PROJECT=<프로젝트ID> ./deploy/vps/create-vm.sh
   ```
   마지막에 공인 IP가 출력됩니다. [`create-vm.sh`](../deploy/vps/create-vm.sh)를 열어 보면 기계 종류(e2-micro), 운영체제(우분투 24.04), 방화벽(80, 443만 열기)이 전부 적혀 있습니다.

## 2. 도메인 만들기 (DuckDNS)

1. <https://www.duckdns.org> 에 GitHub 계정으로 로그인.
2. 원하는 이름(예: `wejump`)으로 서브도메인을 만들고, **current ip** 칸에 서버 IP를 넣고 **update ip**.
3. 페이지 위쪽의 **token** 값을 적어 둡니다 (IP 자동 갱신용, 비밀).

확인:
```bash
dig +short wejump.duckdns.org     # 서버 IP가 나오면 성공
```

## 3. 배포용 열쇠 만들기 (맥에서)

GitHub Actions가 서버에 들어갈 때 쓸 SSH 열쇠 한 쌍을 만듭니다.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/wejump_deploy -N "" -C "github-actions-wejump"
cat ~/.ssh/wejump_deploy.pub      # 공개키 (자물쇠). 서버에 등록. 보여줘도 됨
# ~/.ssh/wejump_deploy            # 개인키 (열쇠). 04에서 GitHub Secret에만 넣음. 절대 공유 금지
```

## 4. 서버 준비 (서버 안에서)

```bash
gcloud compute ssh wejump --project <프로젝트ID> --zone us-west1-b
```

이제 프롬프트가 서버로 바뀌었습니다. 둘러보세요.

```bash
uname -a          # 리눅스 커널
free -h           # 램 1GB
df -h /           # 디스크 30GB
curl ifconfig.me  # 이 서버의 공인 IP
```

그리고 준비 스크립트를 한 번 실행합니다.

```bash
git clone https://github.com/<깃허브아이디>/wejump.git /tmp/wejump
sudo DOMAIN=wejump.duckdns.org \
     DEPLOY_PUBKEY="<3단계에서 복사한 공개키 한 줄>" \
     DUCKDNS_TOKEN=<DuckDNS 토큰> \
     bash /tmp/wejump/deploy/vps/setup.sh
```

[`setup.sh`](../deploy/vps/setup.sh)가 하는 일: Docker 설치, 스왑 메모리 1GB, `deploy` 사용자 생성과 공개키 등록, 코드를 `/opt/wejump`에 받기, `.env` 생성(DB 비밀번호는 무작위로 만들어져서 사람이 볼 일이 없음).

## 5. 손으로 첫 배포

```bash
sudo -iu deploy                      # deploy 사용자로 전환
cd /opt/wejump/deploy/vps
./deploy.sh latest
```

`https://wejump.duckdns.org` 를 열어 보세요. 주소창의 자물쇠를 누르면 인증서 발급자가 **Let's Encrypt**로 보입니다. Caddy가 도메인 이름만 보고 알아서 받아 온 것입니다.

## 6. 서버 안 둘러보기

```bash
alias dc='docker compose -f docker-compose.prod.yml'   # 명령이 길어서 별명 붙이기

dc ps                    # 떠 있는 컨테이너: db, caddy, app-blue
cat Caddyfile            # 지금 손님을 어디로 보내는지
cat .active              # blue
dc logs caddy | grep -i certificate   # 인증서 발급 기록
dc logs -f app-blue      # 실시간 접속 로그. 폰으로 사이트를 열면 여기 찍힘 (Ctrl+C로 종료)
dc exec db psql -U wejump -c "SELECT count(*) FROM messages;"
```

## 7. 보안 확인

맥에서:
```bash
nc -vz -G 3 <서버IP> 443     # 열림 (succeeded)
nc -vz -G 3 <서버IP> 5432    # 닫힘 (timeout). DB는 인터넷에서 접근할 수 없음
```

DB가 안전한 이유는 두 겹입니다. compose 파일에서 DB에 `ports`를 주지 않았고, GCP 방화벽도 80과 443만 열었습니다.
