# 00. 배포란 무엇인가

## 한 문장으로

**배포 = 내 컴퓨터에서만 돌던 프로그램을, 24시간 켜져 있는 다른 컴퓨터에 올려서 누구나 인터넷 주소로 쓸 수 있게 만드는 것.**

`python app.py`로 실행한 프로그램은 내 노트북에서만 돕니다. 노트북을 덮으면 꺼지고, 친구가 자기 폰으로 들어올 방법도 없습니다. 배포는 이 두 문제를 푸는 일입니다.

## 누가 웹사이트 주소를 치면 무슨 일이 일어날까

```
친구의 폰 (브라우저)
  │
  │ ① "wejump.duckdns.org 는 어디야?"  ──▶  DNS: "34.82.1.23 이야"
  │
  │ ② https://34.82.1.23 의 443번 포트로 접속
  ▼
서버 (24시간 켜진 컴퓨터)
  ├─ ③ Caddy     입구 안내 데스크. HTTPS 자물쇠 담당
  │     ▼
  ├─ ④ FastAPI   우리 코드가 도는 곳
  │     ▼
  └─ ⑤ Postgres  글이 저장되는 곳
```

1. **DNS**: `wejump.duckdns.org` 같은 이름을 `34.82.1.23` 같은 IP 주소(서버의 전화번호)로 바꿔 줍니다.
2. **IP와 포트**: IP는 건물 주소, 포트는 호수입니다. 웹은 보통 80호(HTTP)와 443호(HTTPS)를 씁니다.
3. **프록시(Caddy)**: 서버 입구의 안내 데스크입니다. HTTPS 자물쇠를 처리하고, 손님을 알맞은 앱으로 안내합니다.
4. **앱(FastAPI)**: 우리가 짠 코드입니다. 요청을 받아 DB를 읽고 쓰고, 결과를 돌려줍니다.
5. **DB(Postgres)**: 글이 실제로 저장되는 곳입니다. 앱을 껐다 켜도, 새 버전으로 바꿔도 글은 여기 남습니다.

## 이 수업에서 만나는 단어

| 단어 | 쉬운 뜻 | 이 레포에서 어디 있나 |
|---|---|---|
| 서버 / VPS | 인터넷에 연결된 채 24시간 켜진, 빌려 쓰는 컴퓨터 | GCP e2-micro (`deploy/vps/create-vm.sh`) |
| 도메인, DNS | 사람이 외우는 이름 ↔ 컴퓨터 주소(IP) 전화번호부 | DuckDNS |
| HTTPS, 인증서 | 주고받는 내용을 암호화하는 자물쇠. 인증서는 "이 사이트가 진짜"라는 증명서 | Caddy가 Let's Encrypt에서 자동 발급 |
| 프로세스, 포트 | 실행 중인 프로그램, 그 프로그램이 손님을 기다리는 번호 | uvicorn이 8000번에서 대기 |
| 환경변수, 시크릿 | 코드 밖에서 넣어 주는 설정값. 비밀번호처럼 숨겨야 하는 값은 시크릿 | `.env`, GitHub Secrets |
| 이미지, 컨테이너 | 앱+파이썬+라이브러리를 통째로 담은 상자(이미지), 그 상자를 실행한 것(컨테이너) | `Dockerfile` |
| 레지스트리 | 이미지를 올려 두는 창고 | ghcr.io (GitHub 컨테이너 레지스트리) |
| 볼륨, 영속성 | 컨테이너를 지워도 남는 저장 공간. 글이 사라지지 않는 이유 | `pgdata` 볼륨 |
| CI/CD | 코드를 올리면 자동으로 테스트하고(CI) 배포하는(CD) 로봇 | `.github/workflows/deploy-vps.yml` |
| 헬스체크 | "너 건강하니?" 확인 주소 | `/healthz` |
| 무중단 배포 (blue/green) | 손님이 모르게 새 버전으로 갈아 끼우기 | `deploy/vps/deploy.sh` |

## 수업 순서

같은 앱, 같은 `Dockerfile` 하나를 두 가지 길로 배포합니다.

| 단계 | 문서 | 배우는 것 |
|---|---|---|
| 1 | [01-로컬](01-로컬.md) | 내 컴퓨터에서 앱 실행, localhost의 한계 |
| 2 | [02-도커](02-도커.md) | 이미지, 컨테이너, 볼륨 |
| 3 | [03-서버](03-서버.md) | 진짜 서버 만들기, SSH, 도메인, HTTPS, 손으로 첫 배포 |
| 4 | [04-자동화](04-자동화.md) | GitHub Actions로 push하면 자동 배포, 시크릿 |
| 5 | [05-blue-green](05-blue-green.md) | 무중단 배포, 롤백, 로드밸런서 |
| 6 | [06-render](06-render.md) | 같은 걸 PaaS에서 15분 만에. 누가 무엇을 대신해 주나 |
| 참고 | [07-옵션비교](07-옵션비교.md) | 다른 선택지와 비용, 이 구성을 고른 이유 |

**트랙 1 (1~5단계)**: 서버 한 대를 직접 관리합니다. 모든 부품이 파일로 보입니다. 비용 $0.
**트랙 2 (6단계)**: Render가 서버·HTTPS·무중단 배포를 대신합니다. 쉽지만 안이 안 보입니다. 비용 $0.

두 트랙을 다 해 보면 "PaaS가 편한 이유"와 "그 편함 뒤에서 누가 무엇을 하는지"를 동시에 알게 됩니다.
