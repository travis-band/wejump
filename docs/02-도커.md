# 02. 도커: 앱을 상자에 담기

**목표**: "내 컴퓨터에선 되는데 서버에선 안 돼요"를 없애는 방법을 이해한다. 이미지, 컨테이너, 볼륨을 직접 만져 본다.

## 왜 필요한가

앱이 돌려면 코드만 있으면 안 됩니다. 파이썬 3.12, fastapi 0.141, psycopg 3.3… 이 전부가 똑같이 깔려 있어야 합니다. 서버마다 이걸 손으로 맞추는 대신, **앱과 필요한 것 전부를 상자 하나에 담아서** 그 상자를 옮깁니다.

- **이미지**: 상자 (설계도대로 포장된 읽기 전용 파일 묶음)
- **컨테이너**: 상자를 열어서 실행 중인 것 (하나의 이미지로 컨테이너 여러 개를 띄울 수 있음)
- **Dockerfile**: 상자 포장 레시피

## Dockerfile 읽기

[`Dockerfile`](../Dockerfile)을 열어 한 줄씩 봅니다.

| 줄 | 하는 일 |
|---|---|
| `FROM python:3.12-slim` | 파이썬 3.12가 깔린 작은 리눅스에서 시작 |
| `COPY requirements.txt` + `RUN pip install` | 라이브러리 설치. 코드보다 먼저 해서, 코드만 바뀌면 이 단계는 캐시 재사용 |
| `COPY app ./app` | 우리 코드 넣기 |
| `ARG/ENV APP_VERSION` | 빌드할 때 버전 번호를 새겨 넣기 |
| `USER appuser` | 관리자(root) 권한 없이 실행 (보안) |
| `CMD uvicorn ...` | 컨테이너가 시작되면 실행할 명령 |

그리고 [`.dockerignore`](../.dockerignore)를 보세요. `.env`(비밀번호)가 상자 안에 들어가지 않게 막습니다. **이미지는 레지스트리에 올라가서 여러 사람이 받아 갈 수 있으므로, 비밀은 절대 이미지에 넣지 않습니다.**

## 따라 하기

```bash
# 이미지 만들기
docker build -t wejump --build-arg APP_VERSION=my-first .
docker images wejump

# 앱 + DB를 한 번에 (docker-compose.yml에 둘 다 적혀 있음)
docker compose up --build
```

<http://localhost:8000> 을 여세요. 이번에는 파이썬 가상환경 없이, 컨테이너 안의 파이썬이 앱을 돌립니다.

## 컨테이너끼리는 어떻게 찾나

[`docker-compose.yml`](../docker-compose.yml)에서 앱의 DB 주소를 보세요.

```
DATABASE_URL: postgresql://wejump:localdev@db:5432/wejump
```

호스트가 `localhost`가 아니라 `db`입니다. 컨테이너 안에서 `localhost`는 "이 컨테이너 자신"이라 DB가 없습니다. 같은 compose 안의 컨테이너끼리는 **서비스 이름**으로 서로를 찾습니다.

## 실험: 글은 어디에 사는가

```bash
docker compose restart app     # 앱만 재시작 → 글 남아 있음
docker compose down            # 컨테이너 전부 삭제 → 다시 up 하면 글 남아 있음!
docker compose up -d
docker volume ls               # wejump_pgdata 볼륨이 보임
docker compose down -v         # 볼륨까지 삭제 → 다시 up 하면 글이 전부 사라짐
```

컨테이너는 언제든 버리고 새로 만드는 일회용입니다. 오래 남아야 하는 데이터는 **볼륨**(컨테이너 밖의 디스크)에 둡니다. 이 구분이 다음 단계인 "새 버전으로 갈아 끼우기"를 가능하게 합니다.

## 실험: DB 안을 직접 보기

```bash
docker compose up -d
docker compose exec db psql -U wejump -c "SELECT * FROM messages;"
```

화면에 보이던 글이 표로 나옵니다.
