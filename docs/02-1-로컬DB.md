# 02-1. 로컬 DB 띄우고 접속하기

**목표**: 내 컴퓨터에서 Postgres를 도커로 띄우고, localhost로 직접 접속해 본다. 그리고 DB 파일이 실제로 어디에 저장되는지 이해한다.

## 1. 켜고 끄기

레포 폴더에서 실행합니다.

| 명령 | 하는 일 | 글(데이터)은? |
|---|---|---|
| `docker compose up -d db` | DB만 켜기 | 그대로 |
| `docker compose stop db` | DB 멈추기 | 그대로 |
| `docker compose down` | 컨테이너 삭제 | **그대로** (볼륨은 안 지움) |
| `docker compose down -v` | 컨테이너와 볼륨 삭제 | **전부 사라짐** |

## 2. 접속 정보

[`docker-compose.yml`](../docker-compose.yml)에 적힌 로컬 전용 값입니다.

| 항목 | 값 |
|---|---|
| 호스트 | `localhost` |
| 포트 | `5432` |
| 사용자 | `wejump` |
| 비밀번호 | `localdev` |
| DB 이름 | `wejump` |

한 줄로 쓰면 이렇게 됩니다. 이 형식을 **연결 문자열(connection string)** 이라고 부릅니다.

```
postgresql://wejump:localdev@localhost:5432/wejump
          사용자  비밀번호  호스트   포트  DB이름
```

## 3. 접속하는 세 가지 방법

**방법 1. 컨테이너 안의 psql** (따로 설치할 것 없음)

```bash
docker compose exec db psql -U wejump
```

**방법 2. 내 컴퓨터의 psql** (`which psql`로 설치되어 있는지 확인)

```bash
psql postgresql://wejump:localdev@localhost:5432/wejump
```

**방법 3. GUI 도구** (TablePlus, DBeaver, DataGrip 등)
새 연결을 만들고 위 표의 값을 칸마다 넣으면 됩니다.

방법 2와 3이 되는 이유는 compose 파일의 `ports: "5432:5432"` 한 줄 때문입니다. "컨테이너의 5432번을 내 컴퓨터의 5432번에 연결해라"라는 뜻입니다. 이 줄을 지우면 컨테이너 밖에서는 DB에 접속할 수 없습니다. 실제 서버의 compose 파일에는 일부러 이 줄이 없습니다.

## 4. 접속해서 해 볼 것

psql 안에서:

```
\dt                                  -- 테이블 목록
\d messages                          -- messages 테이블 구조
SELECT * FROM messages ORDER BY id;  -- 글 전부 보기
SELECT count(*) FROM messages;       -- 글 개수
\q                                   -- 나가기
```

브라우저로 글을 하나 남긴 뒤 `SELECT`를 다시 해 보세요. 방금 쓴 글이 표에 나옵니다. 화면, 백엔드, DB가 이어져 있다는 게 눈으로 보입니다.

## 5. 같은 DB인데 주소가 두 개인 이유

| 누가 접속하나 | 주소 | 어디에 적혀 있나 |
|---|---|---|
| 내 컴퓨터의 uvicorn, pytest, psql | `localhost:5432` | `.env` |
| 컨테이너로 띄운 앱 | `db:5432` | `docker-compose.yml`의 `app` |

컨테이너 안에서 `localhost`는 "그 컨테이너 자신"이라서 DB가 없습니다. 같은 compose 안의 컨테이너끼리는 서비스 이름(`db`)으로 서로를 찾습니다.

## 6. DB 파일은 어디에 저장되나

### 이미지도, 컨테이너도 아닌 "볼륨"

| 저장 공간 | 성격 | DB 파일을 두면? |
|---|---|---|
| 이미지 | 읽기 전용 설계도 | 쓸 수 없음 |
| 컨테이너 안 | 쓸 수 있지만 일회용 | 컨테이너를 지우면 같이 사라짐 |
| **볼륨** | 컨테이너 밖의 저장 공간 | 컨테이너를 지워도 남음 ✅ |

compose 파일의 이 두 줄이 볼륨을 만들고 연결합니다.

```yaml
volumes:
  - pgdata:/var/lib/postgresql/data   # 볼륨 pgdata를 Postgres의 데이터 폴더에 연결
```

Docker는 프로젝트 이름을 앞에 붙여서 `wejump_pgdata`라는 이름으로 만듭니다.

```bash
docker volume ls
```

```bash
docker volume inspect wejump_pgdata
```

### 맥과 윈도우에서는 VM 안에 있다

컨테이너는 리눅스 커널의 기능으로 만들어집니다. 맥과 윈도우의 커널에는 그 기능이 없어서, **Docker Desktop은 작은 리눅스 가상머신(VM)을 하나 띄우고 그 안에서 Docker Engine을 돌립니다.** 이미지, 컨테이너, 볼륨이 전부 그 VM 안에 있습니다.

```
내 맥 (macOS)
 ├─ docker 명령어 ─── 요청 ───┐      ← 리모컨일 뿐
 └─ Docker Desktop의 리눅스 VM ◀┘
     └─ Docker Engine
         ├─ 이미지
         ├─ 컨테이너
         └─ 볼륨 wejump_pgdata    ← DB 파일은 여기
```

그래서 `docker volume inspect`가 알려주는 `/var/lib/docker/volumes/wejump_pgdata/_data` 경로는 맥 Finder에서 찾을 수 없습니다. 맥이 아니라 VM 안의 경로이기 때문입니다. 맥 입장에서는 VM 디스크 전체가 파일 하나로 보입니다.

```
~/Library/Containers/com.docker.docker/Data/vms/0/data/Docker.raw
```

| 환경 | Docker용 VM | 볼륨이 있는 곳 |
|---|---|---|
| 맥 Docker Desktop | 있음 | VM 안 (Finder에서 안 보임) |
| 윈도우 Docker Desktop | 있음 (WSL2) | VM 안 |
| 리눅스 (예: 03의 GCP 서버) | 없음 | 그 컴퓨터의 `/var/lib/docker/volumes/` 에 바로 |

"Cannot connect to the Docker daemon" 오류가 나는 것도 이 구조 때문입니다. Docker Desktop이 꺼져 있으면 VM도 꺼져 있어서, `docker` 명령어가 요청을 보낼 곳이 없습니다.

### 볼륨 안을 직접 들여다보기

볼륨을 작은 리눅스 컨테이너에 붙여서 열어 보면 됩니다.

```bash
docker run --rm -v wejump_pgdata:/data alpine ls /data
```

`base`, `global`, `PG_VERSION` 같은 파일이 보입니다. 이게 Postgres가 글을 저장하는 실제 파일입니다. 직접 고치면 DB가 망가지니 구경만 하세요.

## 7. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop이 꺼져 있음 | Docker Desktop 앱 실행 |
| `port is already allocated` 또는 `address already in use` | 내 컴퓨터에 이미 Postgres가 5432번에서 돌고 있음 | `lsof -i :5432`로 확인. compose의 포트를 `"5433:5432"`로 바꾸고 `.env`의 주소도 `5433`으로 |
| `connection refused` | DB가 아직 켜지는 중 | 몇 초 뒤 다시. `docker compose ps`에서 `healthy` 확인 |
| `password authentication failed` | compose의 비밀번호를 바꿨는데 볼륨은 옛 비밀번호로 만들어져 있음. 비밀번호 설정은 볼륨을 **처음 만들 때만** 적용됨 | 옛 비밀번호로 접속하거나, 데이터가 없어져도 되면 `docker compose down -v` 후 다시 `up` |
| 글이 다 사라졌다 | `down -v`로 볼륨을 지움 | 볼륨을 지우면 되돌릴 수 없음. `-v`는 신중하게 |
