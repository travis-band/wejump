# 04. GitHub Actions로 자동 배포

**목표**: `main` 브랜치에 push만 하면 테스트 → 이미지 빌드 → 서버 배포가 자동으로 일어나게 한다. 비밀(시크릿)을 코드 밖에 안전하게 두는 법을 배운다.

## CI/CD란

- **CI (지속적 통합)**: 코드를 올릴 때마다 로봇이 자동으로 테스트합니다.
- **CD (지속적 배포)**: 테스트를 통과하면 로봇이 자동으로 배포합니다.

GitHub Actions가 그 로봇입니다. 설명서는 [`.github/workflows/deploy-vps.yml`](../.github/workflows/deploy-vps.yml) 한 파일입니다.

```
git push (main)
   │
   ▼
[test]    DB를 잠깐 띄우고 pytest  ── 실패하면 여기서 멈춤. 고장난 코드는 서버에 가지 않음
   │
   ▼
[build]   Dockerfile로 이미지 빌드 → ghcr.io/<아이디>/wejump:<커밋7자리> 로 올림
   │
   ▼
[deploy]  서버에 ssh 접속 → git pull → ./deploy/vps/deploy.sh <커밋7자리>
```

`deploy` 단계를 보면 [03-서버](03-서버.md)에서 사람이 손으로 친 명령과 똑같습니다. 자동화는 마법이 아니라 **사람이 하던 명령을 로봇에게 대신 시키는 것**입니다.

## 비밀인 것과 비밀이 아닌 것

| 값 | 비밀? | 어디에 두나 |
|---|---|---|
| 서버 주소 (`VPS_HOST`) | 아니요. DNS로 누구나 알 수 있음 | GitHub **Variables** |
| 접속 사용자 (`VPS_USER`, 기본 `deploy`) | 아니요 | GitHub **Variables** (생략 가능) |
| 서버 접속 개인키 (`VPS_SSH_KEY`) | **예**. 이걸 가진 사람은 서버를 마음대로 할 수 있음 | GitHub **Secrets** |
| DB 비밀번호 | **예** | 서버의 `.env`에만. GitHub에도 없음 |
| 레지스트리 로그인 | **예** | `GITHUB_TOKEN`. GitHub가 실행마다 자동으로 만들고 끝나면 버림 |

Secrets에 넣은 값은 다시 볼 수 없고, 로그에 찍히려 하면 `***`로 가려집니다. **코드, 이미지, 로그 어디에도 비밀이 남지 않게** 하는 것이 목표입니다.

## 설정하기

레포 → **Settings** → **Secrets and variables** → **Actions**

1. **Variables** 탭 → New repository variable
   - `VPS_HOST` = `wejump.duckdns.org` (또는 서버 IP)
2. **Secrets** 탭 → New repository secret
   - `VPS_SSH_KEY` = 맥에서 `cat ~/.ssh/wejump_deploy` 한 내용 전체 (`-----BEGIN` 줄부터 `-----END` 줄까지)

설정 전에 맥에서 로봇과 똑같이 접속해 보면 확실합니다.
```bash
ssh -i ~/.ssh/wejump_deploy deploy@wejump.duckdns.org "cat /opt/wejump/deploy/vps/.active"
```

## 확인: 코드 고치고 push

1. `app/static/index.html`의 `<h1>` 글자를 바꿉니다.
2. ```bash
   git commit -am "제목 바꾸기"
   git push
   ```
3. GitHub → **Actions** 탭에서 세 단계가 차례로 초록불이 되는 걸 봅니다 (2~3분).
4. 사이트를 열어 두고 기다리면, 새로고침 없이도 화면 아래 배지 색과 버전 번호가 바뀝니다.

## 실험: 테스트가 배포를 막는다

1. `app/main.py`의 `max_length=30`을 `max_length=0`으로 바꿔서 push.
2. `test`가 빨간불 → `build`, `deploy`는 실행되지 않음.
3. 사이트는 그대로 멀쩡합니다. 고장난 코드는 서버 근처에도 못 갔습니다.
4. 원래대로 고쳐서 다시 push.

## 흔한 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| deploy 단계가 회색(skipped) | `VPS_HOST` 변수가 없음 | Variables에 추가 |
| `Permission denied (publickey)` | 개인키가 잘못 들어갔거나 서버에 공개키가 없음 | 위의 맥 ssh 테스트부터 확인 |
| `denied` / `manifest unknown` (deploy.sh 중) | ghcr 패키지가 비공개 | [03](03-서버.md) 0단계의 Public 설정 |
| `✗ blue 가 건강하지 않습니다` | 새 버전이 `/healthz`에 200을 못 줌 | 로그가 같이 출력됨. 옛 버전이 계속 서비스 중이니 침착하게 |
| 맥에서 `docker pull ghcr.io/...` 할 때 `no matching manifest for linux/arm64` | 이미지는 서버 CPU(amd64, 인텔/AMD 계열)용으로만 빌드됨. M1~M4 맥은 arm64 | `docker pull --platform linux/amd64 ...` (느린 에뮬레이션으로 실행됨). CPU 종류마다 이미지가 다르다는 좋은 예 |
